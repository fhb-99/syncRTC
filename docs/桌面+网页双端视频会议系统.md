# C++/Qt 视频会议系统与 AI 会议助手

## 一、项目定位

本项目基于 C++/Qt、FFmpeg、Boost.Asio、MySQL、Redis 等技术实现一套轻量级视频会议系统，并在会议音频转写的基础上引入大模型能力，提供实时字幕、会议纪要、待办事项提取和会后问答等 AI 会议助手功能。

核心重点放在 C++ 实时音视频链路、网络通信、多线程解耦、服务端房间管理，以及大模型应用集成。

### 项目一句话描述

基于 C++/Qt 与 FFmpeg 实现轻量级视频会议系统，支持会议房间管理、文字聊天、音视频采集编码、UDP 媒体流转发，并接入 AI 会议助手实现实时字幕、会议总结和待办事项提取。

## 三、系统架构设计

### 3.1 整体架构

系统采用“信令通道与媒体流通道分离”的设计：

- 信令通道：使用 TCP 长连接，传输登录、房间操作、成员状态、聊天消息、心跳等可靠消息。
- 媒体通道：使用 UDP 传输音视频帧，基于简化 RTP 包头实现序列号、时间戳和媒体类型标识。
- AI 通道：客户端或服务端将音频片段发送给 AI 服务，AI 服务完成 ASR 转写和大模型总结。

```text
Qt 客户端 A/B
  - 摄像头/麦克风采集
  - FFmpeg 编码/解码
  - OpenGL 渲染
  - SDL2 音频播放
  - 聊天与会议 UI
        |
        | TCP 信令 / UDP 媒体流 / HTTP AI 请求
        v
C++ 会议服务端
  - 网关服务
  - 房间管理
  - 成员状态
  - IM 聊天
  - UDP 媒体流转发
  - 心跳与断线重连
        |
        | 音频片段 / 转写文本
        v
AI 会议助手服务
  - ASR 语音转文字
  - 会议摘要生成
  - 待办事项提取
  - 会后问答
        |
        v
MySQL / Redis
  - 用户信息
  - 会议记录
  - 聊天记录
  - 转写文本
  - 房间状态缓存
```

### 3.2 服务端模块

#### 网关与信令服务

负责维护 TCP 长连接，处理登录鉴权、会议创建、加入会议、退出会议、成员状态同步、聊天消息、心跳检测等请求。

核心技术点：

- Boost.Asio 异步 IO
- 自定义 TCP 消息协议
- 心跳检测与连接状态管理
- 房间内消息广播
- Redis 缓存在线状态

#### 会议房间服务

负责会议生命周期管理，包括房间创建、成员加入退出、主持人权限、成员静音状态、摄像头状态等。

核心技术点：

- room_id 到成员列表的映射
- user_id 到连接对象的映射
- 会议状态广播
- MySQL 持久化会议记录
- Redis 保存在线房间状态

#### 媒体转发服务

采用简化 SFU 模型，服务端不做完整解码和混流，只按房间转发音视频包。

核心技术点：

- UDP 收发媒体包
- 简化 RTP 包头设计
- 序列号和时间戳
- 按房间转发媒体流
- 丢包统计
- 单包大小控制在 1400 字节以内，减少 MTU 分片风险

#### AI 会议助手服务

AI 服务建议作为独立模块实现，初期可以使用 Python 或单独进程提供 HTTP 接口。C++ 主系统通过 HTTP/gRPC 调用 AI 服务。

核心技术点：

- ASR 语音转文字
- 大模型 API 调用
- Prompt 设计
- 会议文本结构化存储
- 会议纪要生成
- 待办事项提取
- 会后问答

### 4.2 音视频采集与编解码

视频链路：

1. FFmpeg 采集摄像头视频帧。
2. 转换为统一像素格式。
3. 使用 H.264 编码。
4. 切分为 UDP 可传输的数据包。
5. 远端接收后解码。
6. 使用 OpenGL 渲染 YUV/RGB 帧。

音频链路：

1. 采集麦克风 PCM 数据。
2. 按 20ms 或固定帧长切片。
3. 编码后通过 UDP 发送。
4. 远端接收并放入播放缓冲队列。
5. 使用 SDL2 播放。

低延迟优化：

- H.264 使用 baseline profile。
- 编码预设使用 ultrafast。
- 关闭 B 帧。
- 采集、编码、发送、接收、解码、渲染队列只保留少量帧。
- 网络抖动严重时优先丢帧，不等待过期帧。

### 4.3 多线程模型

客户端建议拆分为以下线程：

- UI 主线程
- 视频采集线程
- 音频采集线程
- 编码线程
- 网络发送线程
- 网络接收线程
- 解码线程
- 渲染/播放线程
- AI 音频切片上传线程

线程之间通过线程安全队列传递数据，避免 UI 主线程阻塞。

## 五、AI 会议助手设计

### 5.1 功能范围

秋招版本 AI 助手重点实现四个能力：

1. 实时字幕：识别每个参会者的发言内容。
2. 会议总结：会议结束后生成摘要和关键结论。
3. 待办提取：识别“谁在什么时候完成什么事”。
4. 会后问答：基于会议转写内容回答问题。

### 5.2 发言人识别方案

不做复杂的声纹识别。每个客户端只上传自己的麦克风音频，服务端天然知道音频属于哪个 user_id。

转写结果结构：

```json
{
  "meeting_id": "10001",
  "user_id": "u_001",
  "username": "张三",
  "start_time": 12.5,
  "end_time": 16.8,
  "text": "这个接口我下周三之前完成。"
}
```

这种方案简单、稳定、适合学生项目落地。

### 5.3 AI 服务调用流程

```text
客户端麦克风音频
  -> 3-5 秒音频切片
  -> 上传 ASR 服务
  -> 得到转写文本
  -> 服务端保存 meeting_id + user_id + timestamp + text
  -> 客户端显示实时字幕
  -> 会议结束后汇总全文
  -> 调用大模型生成会议纪要和待办事项
```

### 5.4 Prompt 输出格式

会议总结建议让大模型输出结构化 JSON，方便前端展示和存储。

```json
{
  "summary": "本次会议主要讨论了视频会议系统的音视频链路和 AI 助手接入方案。",
  "decisions": [
    "秋招版本优先完成 Qt 双客户端音视频通话",
    "AI 助手先实现实时字幕和会后总结"
  ],
  "todos": [
    {
      "owner": "张三",
      "task": "完成 UDP 媒体包转发模块",
      "deadline": "下周三"
    }
  ],
  "risks": [
    "WebRTC 与自研 RTP 互通复杂度较高，建议放到二期"
  ]
}
```

## 九、简历描述建议

### 项目名称

C++/Qt 轻量级视频会议系统与 AI 会议助手

### 简历写法

基于 C++17、Qt、Boost.Asio 与 FFmpeg 实现轻量级视频会议系统，支持用户登录、会议房间管理、成员状态同步、文字聊天、音视频采集编码与 UDP 媒体流转发。设计简化 RTP 协议，加入序列号、时间戳和丢包统计机制，并通过多线程队列解耦采集、编码、网络发送、接收、解码与渲染流程，降低 UI 阻塞和音视频延迟。

### 面试说明口径

该项目不是商业化替代腾讯会议，而是面向局域网和小规模私有化会议场景的工程原型。秋招版本重点实现会议系统的核心链路，包括信令、房间状态、音视频采集编码、媒体帧转发、多线程解耦，以及 AI 会议助手。生产级能力如复杂 NAT 穿透、大规模 SFU 集群、QoS、自适应码率和安全合规作为后续扩展方向。
